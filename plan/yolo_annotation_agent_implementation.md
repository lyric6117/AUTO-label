# 基于 YOLO 的数据标注 Agent 工程实施规划

## 项目概述

**目标**：构建一个数据驱动的 Agent 系统，将人工标注从「画框」转变为「审核 + 修正 + 决策」，持续减轻标注工作量。

**当前状态**：
- ✅ 已有单视角 YOLO 初版模型
- ✅ 覆盖 2 个零部件，每个零部件有正常/故障（共 4 类）
- ❌ 没有多视角模型
- ❌ 标注成本开始失控

**核心价值**：Agent 决定哪些图片值得人去看，最大化人工标注效率。

**目标**：创建标准化的项目目录结构

**具体步骤**：
1. 创建主项目目录结构
   ```
   tf_infer/
   ├── agent/                 # Agent 核心模块
   │   ├── __init__.py
   │   ├── inference.py      # 推理采集模块
   │   ├── decision.py       # 决策 Agent
   │   └── storage.py        # 数据存储模块
   ├── api/                  # FastAPI 后端
   │   ├── __init__.py
   │   ├── main.py           # API 入口
   │   ├── routes.py         # 路由定义
   │   └── models.py         # 数据模型
   ├── frontend/             # React 前端
   │   ├── package.json
   │   ├── src/
   │   │   ├── App.jsx
   │   │   ├── components/
   │   │   └── utils/
   ├── dataset/              # 数据集目录
   │   ├── v0_seed/         # 初始种子数据
   │   ├── v1_auto/         # 自动标注数据
   │   └── meta/            # 元数据
   ├── config/               # 配置文件
   │   └── agent_config.yaml
   ├── utils/                # 工具函数
   └── tests/                # 测试代码
   ```

2. 创建必要的 `__init__.py` 文件

**验收标准**：所有目录和空文件创建完成

#### 任务 1.2：数据目录结构创建
**目标**：建立版本化的数据存储结构

**具体步骤**：
1. 创建数据集版本目录

   dataset/
   ├── v0_seed/              # 初始种子数据（手动标注）
   │   ├── images/

**验收标准**：目录结构完整，配置文件模板创建

#### 任务 1.3：配置文件准备
**目标**：定义 Agent 的决策规则和系统配置

**具体步骤**：
1. 创建 `config/agent_config.yaml`
   ```yaml
   # Agent 决策阈值配置
   decision:
     auto_accept_threshold: 0.85    # 自动接受阈值
     review_min_threshold: 0.4      # 审核最小阈值
     discard_threshold: 0.4         # 丢弃阈值

   # 模型配置
   model:
     name: "yolov8n"
     path: "models/yolov8n.pt"
     classes:
       - "part1_normal"
       - "part1_fault"
       - "part2_normal"
       - "part2_fault"

   # 数据存储配置
   storage:
     base_path: "dataset"
     current_version: "v1_auto"
     db_path: "data/agent.db"

   # API 配置
   api:
     host: "0.0.0.0"
     port: 8000
     cors_origins: ["http://localhost:3000"]
   ```

2. 创建配置加载工具函数

**验收标准**：配置文件完整，可正确加载

### 阶段二：核心模块开发（预计 2-3 天）

#### 任务 2.1：推理采集模块开发
**目标**：实现 YOLO 模型推理和结果采集

**具体步骤**：
1. 实现 `agent/inference.py`
   - 加载 YOLO 模型
   - 批量推理接口
   - 输出标准化的检测结果 JSON 格式：
     ```json
     {
       "image": "xxx.jpg",
       "detections": [
         {
           "cls": "fault_A",
           "conf": 0.91,
           "bbox": [x, y, w, h]
         }
       ]
     }
     ```
   - 保留原始置信度（关键）

2. 实现推理结果验证
   - 检查输出格式
   - 验证 bbox 坐标有效性

**验收标准**：能成功推理并输出标准格式结果

---

#### 任务 2.2：决策 Agent 模块开发
**目标**：实现基于置信度的自动决策逻辑

**具体步骤**：
1. 实现 `agent/decision.py`
   - 决策规则实现：
     ```python
     if conf >= 0.85:
         action = "auto_accept"
     elif 0.4 <= conf < 0.85:
         action = "send_to_review"
     else:
         action = "discard"
     ```
   - 批量决策接口
   - 决策统计功能（接受/审核/丢弃数量）

2. 实现决策策略扩展接口
   - 支持后续添加更复杂的决策规则
   - 支持基于类别的差异化阈值

**验收标准**：决策逻辑正确，统计功能完整

---

#### 任务 2.3：数据存储模块开发
**目标**：实现检测结果和人工修正结果的持久化

     - `detections`：检测结果
     - `reviews`：人工审核记录

   - CRUD 操作接口

2. 实现文件系统操作
   - 图片和标签文件存储
   - 检测结果 JSON 存储
   - 数据版本目录管理

**验收标准**：数据库操作正常，文件存储正确

### 阶段三：Web 界面开发（预计 3-4 天）

#### 任务 3.1：后端 API 开发
**目标**：提供完整的 RESTful API 接口

**具体步骤**：
1. 实现 `api/main.py`
   - FastAPI 应用初始化
   - CORS 配置
   - 中间件配置

2. 实现 `api/routes.py`
   核心接口：
   - `POST /api/inference`：上传图片进行推理
   - `GET /api/review/queue`：获取待审核队列
   - `POST /api/review/accept`：接受检测结果
   - `POST /api/review/modify`：修正检测结果
   - `POST /api/review/reject`：拒绝检测结果
   - `GET /api/stats`：获取统计信息
   - `GET /api/versions`：获取数据集版本信息

3. 实现 `api/models.py`
   - Pydantic 数据模型定义
   - 请求/响应验证

**验收标准**：所有接口可正常调用，返回正确数据

## 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| YOLO 模型推理速度慢 | 用户体验差 | 优化推理代码，考虑批量处理 |
| 前端 Canvas 性能问题 | 标注卡顿 | 使用虚拟化，限制同时显示的框数 |
| 数据库并发问题 | 数据不一致 | 添加事务和锁机制 |
| 决策阈值不合理 | 标注效率低 | 提供动态调整接口，基于数据统计优化 |
